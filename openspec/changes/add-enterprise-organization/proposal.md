## Why

平台目前只有「个人用户 + 个人钱包」一种计费主体。企业客户需要统一付费、统一管控：由企业承担全体成员的调用费用，按公司 / 部门 / 员工三级设置消费上限，并按企业内角色分层查看使用记录。现有 `admin`/`user` 两种系统角色和个人余额模型无法表达这种组织关系。

## What Changes

- 新增「企业」计费主体：企业有自己的余额与余额流水，余额只能由系统管理员在后台调整（充值 / 扣减），全部写入企业余额流水。
- 新增企业内角色（与系统角色 `admin`/`user` 正交）：
  - `owner` 企业负责人：管理整个企业，查看全企业使用记录。
  - `manager` 部门负责人：查看本部门全部成员的使用记录，按企业开关决定能否管理本部门成员。
  - `member` 员工：只能看到自己的使用记录。
- 新增组织架构：企业下的一级部门（不嵌套）。每个成员最多属于一个部门，可以不属于任何部门（直属企业）。
- 新增三级限额：企业、部门、成员三个层级各自可设置日 / 周 / 月 / 累计总额四个 USD 上限（不设即不限，0 表示禁用）。请求 preflight 时任一层级超限即拒绝；请求结算后用量同时计入成员、所在部门和企业三个层级。
- 企业成员不再使用个人钱包：
  - 成员在企业期间的余额模式消费全部从企业余额扣除，preflight 检查企业余额而不是个人余额。
  - 个人余额保持冻结，不扣也不展示；个人充值、兑换余额码等入口对企业成员关闭。
  - 成员被移出企业后恢复为普通用户，个人余额原样可用。
- 两种添加员工方式：
  1. 系统管理员在后台把已有用户加入某企业，或直接为企业创建新用户。
  2. 企业侧新增员工：企业负责人（以及开关允许时的部门负责人，仅限本部门）直接创建新账号并加入企业。
- 使用记录按角色分层可见：员工 → 本人；部门负责人 → 本部门（按消费发生时所在部门）；企业负责人 → 全企业（按消费发生时所在企业，成员离开后历史记录仍归企业）。
- 可见性开关（企业级设置，系统管理员和企业负责人可修改）：
  - 企业余额对部门负责人 / 员工是否可见。
  - 员工限额（及用量）对员工本人 / 部门负责人是否可见。
  - 部门限额对部门负责人是否可见。
  - 部门负责人能否在本部门新增 / 移除成员、调整成员限额。
- 分组访问限制：
  - 系统管理员为企业配置「可用分组池」，可包含专属分组（相当于授权给全体成员）；分组池非空时成员个人的分组授权在企业期间被忽略。
  - 企业在分组池内配置企业级、部门级、成员级三级分组白名单，成员有效可用分组为分组池与各已配置层级的交集。
  - 创建 / 修改 API Key、可选分组列表、网关请求三处生效；白名单收紧后已绑定旧分组的 Key 立即被拒（`ENTERPRISE_GROUP_NOT_ALLOWED`）。
- 补充能力：
  - 企业状态（启用 / 停用）：停用后全体成员的网关请求被拒绝。
  - 成员状态（启用 / 停用）：企业内停用某成员，不影响其账号登录，但其网关请求被拒绝。
  - 企业侧使用统计（今日 / 本月消费、按成员 / 部门 / 模型汇总）。
  - 企业操作审计日志：成员增删、角色变更、限额变更、余额调整、设置变更。

## Capabilities

### New Capabilities
- `enterprise-organization`：企业、部门、成员与企业内角色的数据模型、管理端与企业侧管理接口、员工两种添加方式、移出与停用。
- `enterprise-billing`：企业余额与余额流水、成员请求改扣企业余额、个人钱包冻结、三级限额 preflight 与用量累加。
- `enterprise-group-access`：企业可用分组池、三级分组白名单、绑定与网关运行时校验、认证缓存失效。
- `enterprise-visibility`：按企业内角色分层的使用记录与统计可见范围、余额与限额的可见性开关。

## Impact

- **数据库**：新增 `enterprises`、`enterprise_departments`、`enterprise_members`、`enterprise_quotas`、`enterprise_balance_logs`、`enterprise_audit_logs`、`enterprise_allowed_groups`、`enterprise_group_whitelists` 表；`usage_logs` 新增可空列 `enterprise_id`、`enterprise_department_id` 及部分索引。
- **后端**：计费 preflight 与扣费链路、API Key 认证快照、`User.CanBindGroup` 与网关分组校验、分组删除清理、使用记录写入与查询、个人充值 / 兑换入口拦截、管理端与用户侧新路由。
- **API**：新增 `/api/v1/admin/enterprises/...` 与 `/api/v1/enterprise/...`；`/api/v1/auth/me`（或当前用户接口）返回企业成员信息。
- **前端**：管理端「企业管理」页面；用户侧「我的企业」页面（按角色显示组织架构、成员、限额、使用记录、设置）；企业成员隐藏个人充值入口、按开关展示企业余额。
- **兼容性**：非企业成员的行为完全不变；`usage_logs` 新列可空，历史数据无需回填。
